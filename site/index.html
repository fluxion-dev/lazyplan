Agent coordination

Two agents, one plan, no collisions.

Claims are short leases with an expiry, not permanent owners. Work stays visible, handoffs stay on the row, and blocked work stops looking available.

Claim atomically

lpui next takes the first eligible todo and moves it doing. Renew the lease while you work; release it when you stop. Expired leases are reclaimable.

Hand off in place

Notes are append-only on plans, milestones, and tasks. Blocking releases the claim, records the reason, and keeps status honest without a fourth state.

See what needs attention

The Attention source filter surfaces expired claims, blocked tasks, aging doing work, done rows with open criteria, and red PR checks. The status line reports the count.

Git + PR provenance

See where the plan landed in the source.

Link commits to tasks, then press g to follow the evidence from plan element to repository, branch, commit, changed file, and pull request.

Source trail

A keyboard tree groups each checkout by repository, commit, and changed file. Plans and milestones roll descendant work up, so plan-level proof is one key away. Highlight a commit or file to read its unified diff in place, with old and new line numbers and explicit binary, root, merge, empty, and missing states.

Open or copy fast

Open a commit, PR, or file in the browser. Copy a SHA, path, or URL without leaving the terminal. Filter the trail when a plan touches many files.

Read-only by design

lazyplan records existing branches and commit proof. It never commits, pushes, opens PRs, or merges; your existing tools stay in charge of VCS actions.

Trace the proof

criterion relate links an acceptance item to the task that proves it. trace walks to commits and PRs; lint --strict fails on uncovered criteria and weak task descriptions.

Gate done on evidence

task finish --require-pr --require-checks reads cached PR and CI state. A missing or red check keeps the task doing; an override records why.

One checkout, one branch

Starting a task records an existing branch. A second open task on the same checkout or remote branch is rejected with the owner named, so agents do not race the same working tree.

Works with the tools you already use

  • Commits: link a SHA, capture a task finish range, or scan Lazyplan trailers.
  • Branches: record an existing branch and base before the work starts.
  • Pull requests: refresh cached state, checks, reviews, and merge evidence from GitHub.
  • Filters: show only linked work, PRs, stale links, or unlinked rows.

🚀Quickstart

Three commands. One plan.

Linux and macOS

cd ~/my-plan
lpui                     # first run sets up agents, skills, hooks, and the plan store
lpui plan add --title "my-plan" --why "reason" --what "scope"
lpui

Windows PowerShell

PS> cd $HOME\my-plan
PS> lpui                     # first run sets up agents, skills, hooks, and the plan store
PS> lpui plan add --title "my-plan" --why "reason" --what "scope"
PS> lpui

Working with a team? lpui setup --placement repo shares the plan in the repo. Check what setup resolved with lpui doctor.

🤖For your coding agent

Your agent gets the same plan through a typed MCP server or a simple command line. It can claim work, add proof, leave a note, and keep you posted.

lpui mcp                              # typed tools + resources on stdio
lpui --porcelain next                 # claim the first eligible task
lpui --porcelain stats --since 7.days # WIP, cycle time, aging, stale work
lpui --porcelain note add --kind task --id 3 --text "Handoff"
lpui --porcelain task finish --id 3 --require-pr --require-checks
lpui --porcelain issue import --provider github --repo owner/repo

MCP exposes read tools for the brief, plans, rows, claims, audit, trace, lint, and info, plus writes for the journal, criteria, claims, notes, blocked work, and commit links. --read-only hides writes for reviewers and never creates a missing database.

Without MCP, porcelain mode answers each write with one tab-separated row and keeps overview reads glyph-free, so your agent spends context on the plan instead of decorations. The columns are kind, id, status, title, parent, and extra; --json is still there when you need full fidelity.

You set the direction. It does the busywork.

Setup installs read-only lifecycle hooks for detected agents, so a session starts with the active task and a commit reminds you to link it. Hooks never move work or write to the database; remove them with lpui setup --no-hooks. On Windows they run in Git Bash or PowerShell, and both find lpui on PATH.

FAQ

Questions, answered.

The short version of how lazyplan fits your terminal, your agent, and your git workflow.

What is lazyplan?

lazyplan is a terminal plan tracker for you and your coding agent. Plans, milestones, tasks, and acceptance criteria live in one local place, with claims, notes, proof, and flow health alongside them, so you can steer the work without losing context in chat.

Does lazyplan run on Windows?

Yes. Install with pipx install --backend pip lazyplan-tui. The shared home is %LOCALAPPDATA%\lazyplan, the default actor is %USERNAME%, and Claude Code hooks match both Git Bash and PowerShell. Plan text is read as UTF-8 or UTF-16 with a BOM and written as UTF-8.

Does lazyplan work with coding agents?

Yes. Your agent uses the same local database through the lpui command line or the local MCP server, so it can read the plan, claim work, add proof, and move tasks forward while you keep the plan visible in the TUI.

How do claims stop two agents from taking the same task?

lpui next atomically claims the first eligible todo with a renewable lease. A claim carries the actor, start, expiry, and an optional note. Expired leases are reclaimable; renew or release while you work. Blocking a task releases its claim and records the reason, so next skips it until it is unblocked.

Does lazyplan expose an MCP server?

Yes. lpui mcp serves JSON-RPC over stdio with no extra dependency. It exposes read tools, write tools, and brief/plan resources. --read-only hides and rejects writes, and never creates a missing database.

Does lazyplan create commits, push branches, or open pull requests?

No. lazyplan is read-only on the VCS front. It records existing branches, links commits, and caches pull request proof, but other tools remain responsible for committing, pushing, reviewing, and merging.

How does git and pull request provenance work?

Link a commit to a task, or finish a task on a recorded branch. lazyplan can refresh linked commits into pull requests and cache checks and merge state. Press g in the TUI to browse repository, commit, changed file, and PR evidence for any plan, milestone, or task. Highlight a commit or file to read its unified diff in place, bounded to keep the pane readable; o opens the full commit.

Can lazyplan gate a task on a PR or CI?

Yes, opt in with task finish --require-pr or --require-checks. Gates read cached PR and check state, so run pr refresh first. A failure exits 2 and leaves the task doing with no commits linked. --override REASON records the exception and completes normally.

Does lazyplan write back to GitHub or Linear?

No. issue import is one-way: GitHub issues come from the live API, Linear from a JSON export, and both become plans or tasks with a source ref. Re-import refreshes only cached source metadata. lazyplan never edits, closes, or comments on provider issues and never stores tokens or raw payloads.

How does sharing and sync work without a server?

lpui share --plan 1 writes a standalone escaped HTML or safe JSON snapshot. Plans also carry stable UIDs, so lpui sync --file dump.json can add unknown plans, skip identical ones, and report conflicts without deleting or overwriting local work. Merge is plan-granularity, not row-level.

How do marks and bulk edits work?

Press space to mark rows for the session. The palette can bulk move to doing or done, block with a reason, release claims, clear marks, and undo the last status or block change once. Bulk delete and archive stay single-row because undo cannot safely recreate subtrees.

Where is my plan data stored?

Plans live in a local SQLite database, shared in your home by default or inside a repository with team scope. There is no account or cloud dependency, and you can back up or restore everything with lpui export and lpui import.

Is lazyplan fast with large plans?

Reads are batched. On an 88-plan, 789-task benchmark the tree dropped from 909 queries to 12, list --json from 7,853 to 18, export from 18,612 to 26, and TUI refresh from 5,148 to 139. Query budgets gate CI on Linux, macOS, and Windows.

How do I install lazyplan?

Install with pipx install lazyplan-tui, or use pipx install --backend pip lazyplan-tui on Windows. Linux deb and rpm packages and the install script are also available. Python 3.11 or newer is required.

Install with pipx

The recommended path. One command, no clutter.

pipx install lazyplan-tui

PS> pipx install --backend pip lazyplan-tui
